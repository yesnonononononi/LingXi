
## 约定修正：ClientException 允许带 message；业务失败一律 throw

**用户明确纠正**：「ClientException::new 不是只能用无参构造，可以加 message 区分」。此前 MEMORY.md 的表述（`orElseThrow(ClientException::new)` + 禁 `Result.error` 堆叠）写得过于字面，容易被读成"只能无参"。

**修正后的约定**：
- 业务失败一律 `throw new ClientException(message)`，**不走返回值**
- `ClientException(message)` → `GlobalExceptionHandler.handleClientException` → `Result.error(e.getMessage())` → HTTP 200 + code≠1 + errMsg 透给前端 `isOk()`
- 无参 `ClientException()` 仅用于「原因无需区分」的兜底
- `Result` 只用于表达**成功**（`Result.success(...)`）
- 特殊语义走专用子类 + 专用 handler：`AccessDeniedException`(403)、`SessionNoFoundException`/`WorkspaceNoFoundException`(403)

**全项目一次性收敛（用户选择）**：15 处 `return Result.error(...)` → `throw new ClientException(...)`，覆盖 6 个文件：
- `AgentServiceImpl`（4 处，含 `findById` 的 `orElseGet` 一并改）
- `TeamServiceImpl`（4 处）
- `SessionServiceImpl`（5 处，含 `bindWorkspace` 这个纯拒绝方法）
- `WorkspaceServiceImpl`（5 处）
- `ExecutionServiceImpl`（2 处，含 `orElseGet`）
- `UserConfigServiceImpl`（1 处）
收敛后业务层 `return Result.error` **零残留**，只剩 `GlobalExceptionHandler` 内部的构造（正常职责）。清理了各文件不再使用的 `java.util.Optional` import。

**⚠️ 一处刻意保留的例外：`WorkspaceServiceImpl.findByDir`**
它原本 `return ws != null ? success(toVO(ws)) : Result.error("工作空间不存在")`。改为 **`Result.success(null)`**，理由：
- 该方法语义是「**探测**这个目录是否已登记」，查不到是**正常业务结果**，不是错误
- `CallSubAgentTool:262` 直接依赖 `findByDir(workDir).getData()` 为 null 来判定「沙箱路径不可直用」
- 两个测试 `CallSubAgentMemberWiringTest:139`、`CallSubAgentToolWorkspaceTest:49` mock 的就是 `Result.success(null)`
- 若改成 throw 会把调用方**正常分支变成异常流**
- 区分原则：按**主键**取资源，取不到 = 资源不存在 = 错误（`findById`）；按**业务键探测**，查不到 = 探测结果为否 = 正常返回 null（`findByDir`）
- 已在该方法 javadoc 写明这个区别
