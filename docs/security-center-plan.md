# 安全中心实施与验证

## 范围与恢复点

旧状态恢复提交：框架 e66f5a5、业务 b3307cd。它们是源码恢复点，不是用户文件自动备份。

第一版按照用户确认：使用原生沙箱拒绝预设隐私目录，覆盖文件工具和终端子进程；文件审批以后再做。普通目录允许跨项目访问。MCP 单独评估，不为了接入审批或代理引入复杂流程。正式发布、打标签、上传安装包须用户另行批准。

## 三张本地 JSON 表

sandbox-security-rule-files.json、sandbox-security-rule-terminal.json、sandbox-security-rule-net.json 使用同构规则集合，分别落盘到现有配置目录。仓储继承 AbstractJsonRepository，复用文件锁、原子替换及事务支持。整套规则带 revision，比较与替换在同一锁内完成；并发冲突拒绝覆盖。规则是值对象，前端新增草稿不伪造业务 ID。

GET /sandbox/security/{files|terminal|net} 返回权威规则、版本、动作与生效方式；PUT 校验并保存；POST /sandbox/security/{category}/defaults 获取预设草稿，保存后才覆盖。加载失败不伪造配置，保存失败保留编辑。

## 文件权限：原生禁止或允许访问

预设 .ssh、.aws、.gcp、.gnupg、.azure、.config/gcloud、.netrc、.git-credentials 默认禁止；用户可增删、启停及修改，也可添加自定义路径。环境变量只展开明确支持的用户目录形式。读取配置后也要校验，不能靠手改 JSON 绕过不支持动作的检查。

当前 MXC 的 deniedPaths 会同时禁止读取、写入、删除。界面采用统一访问动作，后端拒绝混合权限及文件 ASK。禁止规则直接进入原生配置，不由工具字符串扫描模拟；原生拒绝优先，宽泛允许不能覆盖。不存在的路径也保留拒绝策略。应用配置固定拒绝，运行资源和控制目录不能被普通规则授予写入。

Windows 通过显式卷根只读与普通目录读写授权开放其他项目，同时避开运行资源。卷根及运行资源上层的单个文件保守只读；否则逐文件授权正在使用的注册表、临时文件会触发共享冲突。重解析点不单独授予写入权限。普通宿主 ACL 仍适用。Linux 暂保留工作区授权，框架拒绝 Linux ambientRoots，不能宣称跨平台具有相同的全盘策略。

文件策略在每次新建执行解析工作空间时生成快照，运行中的执行不会自动更换；界面说明了生效时机。只读模式不给普通目录写入授权，隐私禁止仍保留。

## 命令规则与审批

程序名和命令前缀支持允许、询问、禁止。禁止优先，其余按列表首条匹配；未命中沿用现有通用命令权限。毁灭性命令仍不能通过自定义允许规则绕过。命令文本规则不声称拦截任意脚本内部行为，隐私路径由原生文件隔离覆盖。

询问复用已有持久化命令审批，不增加文件审批载荷或恢复分支。批准后的实际执行重新检查最新禁止规则，旧审批不能越过新禁止。规则每次从本地表读取并校验。

## 网络与 MCP 的实际范围

网络表第一版固定默认允许，不接受尚未实现的域名或 HTTP 过滤配置。原生策略开启普通出站访问，并有宿主正对照和沙箱内公共端点连接验证。当前 Windows 实测不支持 hostLoopback: allow，强行打开会在创建沙箱前失败；适配器仍保留入站和宿主回环限制，界面明确显示，不能写成完全无限制网络。

业务 MCP 暂沿用宿主连接，包括远端 HTTP 与 stdio，保持联网能力，但不受本轮原生隐私目录拒绝约束。删除未接入的业务隔离辅助类，避免源码看似保护而实际仍使用宿主池。框架已有工作区 stdio 启动能力并运行隔离集成测试，可供下一轮复用。

成本判断：stdio 改接入现有工作区启动入口的代码量较小，但需要补全依赖可读授权、安装/发现、握手失败诊断、暂停恢复和请求资源关闭测试，完整接入成本中等。HTTP 客户端的隔离不会隔离已在宿主运行的 MCP 服务；本地 HTTP MCP 的隐私保护还需要隔离服务部署，成本更高。本轮不把宿主 MCP 标成已保护。

## 验证与交付纪律

规则表测试覆盖持久化回读、独立表、并发版本冲突、预设、自定义、非法动作。移除版本比较时测试变红；恢复后通过。

原生 Windows 夹具覆盖所有本地卷的普通目录跨项目读写、CMD dir、文件工具及子进程隐私拒绝、未来路径、运行资源写入拒绝、目录别名及只读模式、公共 TCP 出站。移除原生隐私拒绝后，实际读取回归因“不再抛出拒绝异常”变红。

界面保留原有灰阶、字体、圆角和深浅色，实际设置弹窗验证增删、启停、排序、保存失败保留草稿、重置、版本与窄屏。框架与业务测试通过后推送框架并安装，业务锁定准确版本和完整 SHA，从锁定源码准备隔离 Maven 仓库再次验证，再提交推送业务。正式发布等待用户批准。
