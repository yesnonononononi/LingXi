# 生图工具

在「设置 → 模型 → 其它模型配置」分别选择压缩模型和生图模型。生图模型仍在模型列表维护连接信息，调用方式选「图片模型」；对话与智能体基座选择文本模型。

主模型根据完整会话组织提示词，再调用 `generate_image`：

```json
{"prompt":"夕阳下的红色帆船，白帆，插画风格","path":"art/sailboat.png"}
```

`size`、`quality`、`count` 都可以不传，只有 `prompt`、`path` 必填。默认尺寸优先采用生图模型配置；未配置时为 `1024x1024`。默认质量沿用模型配置，未配置则由服务端决定。每次只生成一张图片，`count` 默认且仅支持 `1`，不会继承模型配置中的批量数量。

需要覆盖规格时：

```json
{"prompt":"夕阳下的红色帆船，白帆，插画风格","path":"art/sailboat-wide.png","size":"1536x1024","quality":"high"}
```

本地只做基础格式校验：`size` 必须为正整数宽x高（如 `1536x1024`）或 `auto`，`quality` 必须为非空白字符串。工具不维护模型白名单、尺寸档位、边长、比例、像素数或质量枚举限制。格式正确的规格直接交给模型；服务端拒绝时，工具返回包含服务端错误信息的失败结果，供主模型决定如何调整参数。

- `path` 必须为工作区内的相对文件路径，支持 `.png`、`.jpg`、`.jpeg`，已有文件不覆盖。
- 文件通过工作区桥接写入，本地和沙箱共用此工具。预览副本位于数据目录，通过 `/a/images/...` 查询。
- 回执提供 `path`、`previewUrl` 和文件大小。主模型可用 Markdown 图片展示预览，继续执行其它任务。
- 生图模型的用量汇总到当前执行；生成成功但保存失败时，已返回的模型用量仍计入。

`user_configs` 新增设置字段：

| 字段 | 含义 |
| --- | --- |
| `imageModelId` | 生图模型 ID；显式 `null` 关闭，不传保持原值 |
| `imageGenerationMaxCalls` | 每次执行最多调用次数；默认 3，范围 0～20，0 禁用 |

次数按工具调用计数，失败也占用。调用前保存执行配额，同一轮多个请求共用上限；暂停、恢复不会重置，新执行单独计数。SDK 自动重试关闭，避免一次工具调用隐含多次生成请求。

设置沿用现有 JSON 配置仓储。H2 的 V2 脚本同步补齐表字段，V1 基线指纹保持原样。升级后重启后端，在其它模型配置中选择已有图片模型即可使用；历史图片消息继续使用原渲染链路。
