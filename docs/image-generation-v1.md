# 生图模型第一版

模型新增和编辑页面提供「调用方式：对话 / 生图」。生图选择保存在既有 `provider` 字段中，值为 `default-image-model`，不按模型名称自动判断。

选择该模型后，在普通会话中发送提示词即可生成图片。第一版只使用当前用户提示词，不把系统提示、工具定义或整段聊天历史拼成生图提示；暂不支持图片编辑、蒙版和多轮改图。

## 消息链路

- 框架通过独立生图调用器调用 `ImageModel`，沿用响应身份和用量结算。
- 输出图片进入 `AiMessageEntity.images`。业务落库前将 PNG/JPEG 数据保存至会话图片目录，再把图片地址记录到消息和执行快照。
- 纯图片回复也会形成正文块。历史查询和实时终态快照共用 `TextBlock.imageUrls`，前端不解析厂商原始响应。
- 现有图片组件负责展示、加载失败重试和大图预览。没有图片字段的旧消息保持原行为。

SDK 尚不支持将助手生成的图片作为聊天输入回放。切回文本聊天模型时，只传递已生成图片数量的说明，不把图片字节当成文字发送。需要分析生成图时，应通过已有图片输入能力明确提供图片。

## 验证

`ImageGenerationFlowTest` 默认使用本地模拟端点，覆盖配置保存、调用策略、消息落库、终态快照、历史恢复与图片查询。

真实网关测试必须显式启用 `lingxi.image.live=true`，并通过进程环境 `LX_LIVE_IMAGE_KEY` 提供凭据。测试使用独立临时配置目录，结束后清理；可通过 `lingxi.image.output` 导出不含凭据的历史、快照和图片，用于前端组件回放。

前端定向验证命令为 `npm run test:message-images`；设置 `LX_IMAGE_BUSINESS_REPORT` 后可回放真实后端导出的报告。普通门禁不会发起真实生图请求。
