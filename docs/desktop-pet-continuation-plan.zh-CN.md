## 4. 技术路线与边界

继续复用当前独立 `pet.html`、表现指令总线、分层合成器、资产生成/校验和 Electron 窗口管理，不整体推翻。建议采用「姿态动画资产 + 现有分层微动态 + 桌面空间控制」路线。

站姿的耳尾摆动适合当前分层方案；坐、趴、蜷睡、跑跳涉及整体轮廓变化，应补对应原画和关键帧。不能仅旋转/压扁当前站姿来验收。Live2D 可以在资产与绑定确有收益时作为后续表现实现；它不能替代桌面移动和原生窗口检测，本方案不把切引擎当作全机制前置条件。

### 4.1 表情与资产先补齐

优先补「不含脸区的主体 + 对齐的脸区替换层」，复用现有 P0 可用脸区。脸层必须去掉被替换的底像素，不能把带耳朵/发夹的整个头重复盖到 P1 上。构建时验证默认重组、所有表情轮廓、透明边缘与遮挡关系。

新增 wink 独立表情；blink 的睁/半闭/闭眼序列独立维护，不能让 wink 取代闭眼或让困倦的嘴型随眨眼跳动。所有既有 8 档表情与新增 wink 都必须在默认 layered 模式肉眼可见。

美术交付按姿态拆批：坐姿及抱云、左右走路、左右跑步、起跳/腾空/落地、趴下/起身、趴睡/惊醒、玩耍、窗口探头/扒边、侧后方向、60px 迷你。每批先验静帧，再补动作过渡，最后接入工程。

每种姿态定义逻辑画布、可见边界、脚底/身体接触点、握持点、命中区域和方向。保留旧站姿 2048×3072 的既有契约；横向趴姿使用明确的姿态几何，不强迫沿用站姿 2:3 包围框。蝴蝶结/发夹有不对称性，左右资产不能只盲目镜像。

### 4.2 行为、位置与画面分工

- 行为状态机决定待机、走跑、跟随、趴卧、睡眠、玩耍与打断；时间和随机源继续注入，便于重放。
- 新增独立移动控制模块，拥有桌面位置、速度、朝向和支持面；拖拽与自主移动只能有一个位置写入者，不能两个定时器抢窗口。
- 表现层消费姿态/表情/动作和运动相位，不自行轮询全桌面，也不自行改权威窗口位置。
- 桌面环境适配器提供显示器、鼠标、任务栏和其他窗口的真实几何及有效性；渲染进程只接收白名单数据。
- 小云酱先作为同一宠物窗口内的独立角色与时间轴，拥有相对坐标和遮挡顺序；先完成抱起/玩耍，暂不为伙伴额外创建原生窗口。

交互打断顺序建议：关闭/隐藏与环境失效收尾 → 用户拖拽 → 点击/唤醒/抚摸 → 主动指定玩法 → 自主走跑/玩耍 → 闲置睡眠与待机。仍需保留现有通道隔离，不能用 force 无条件覆盖所有动作。用户刚互动时刷新闲置时间，自主眨眼/摆尾不刷新。

跳跃的视觉高度与地面移动分开表示，影子保持在支持面；走跑步频由实际速度驱动。支持面或目标窗口消失时，取消绑定并转移到最近合法工作区，不能保存一个已失效句柄当作下次启动依据。

### 4.3 Windows 场景适配

鼠标跟随可沿用 Electron 主进程 `screen.getCursorScreenPoint()`，通过停止半径、方向滞回与平滑加减速避免抖动。Electron 的坐标接口涉及 DIP/物理像素，适配器应统一输出 DIP，不能把不同来源的坐标直接相减。参见 [Electron screen](https://www.electronjs.org/docs/latest/api/screen)。

其他应用窗口检测建议用随包的 Windows 原生辅助程序，先做一个可安装验证的探针，再固定实现方式。`EnumWindows` 可枚举桌面应用顶层窗口；可见边缘使用 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` 并处理 DPI。辅助程序需过滤自身、不可见/最小化等窗口，并检验支持边缘是否被遮挡。API 的存在不等于已经解决所有 Windows 窗口类型，实际支持矩阵需实测。参见 [EnumWindows](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumwindows) 与 [GetWindowRect 的边框及 DPI 说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect)。

任务栏需要区分工作区边缘和真实任务栏位置。`ABM_GETTASKBARPOS` 仅针对系统任务栏，不能据此声称支持所有副屏任务栏；副屏、自动隐藏、顶部/侧边任务栏要列入探针与验收。参见 [SHAppBarMessage](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shappbarmessage)。

所有停靠坐标以角色接触点计算。例如脚底贴窗口上沿时，应由目标屏幕接触点反算窗口左上角，计入画布留白、顶部气泡和缩放。不能把整扇桌宠窗口底边贴过去，否则原图中的脚/手会悬空。

### 4.4 设置与功耗

补齐桌宠开关、100/125/150px、60px 迷你、鼠标跟随、自由活动、任务栏/窗口互动、夜间睡眠时段和召回；沿用本机偏好，不引入后端业务持久化。关闭仍沿用原生右键菜单与托盘恢复。

隐藏时停止移动、环境采样和非必要动作计时；跟随/移动时按需启动单一时钟，站定后停钟；被支持的窗口移动时以事件为主、低频校准为辅。减少动态效果时保留必要反馈与用户手动拖拽，关闭自发奔跑/跳跃等大幅运动。

## 6. 验收与回归纪律

1. 为上表每个编号记录触发步骤、预期画面、退出路径、对应测试、录屏/截图及被测提交。开发调试入口仅用于定位；最终必须从右键菜单、鼠标或时间事件到画面贯通。
