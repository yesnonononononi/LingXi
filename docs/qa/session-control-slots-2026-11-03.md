# 会话树控制槽收拢验收

## 实现边界

- 删除业务注册表中的 `Thread`、`ChildPhase`、挂起阶段同步，以及输入唤醒中的无效取消查询。
- `SessionExecutionRegistry` 按根会话持有主、子执行槽，并按执行 ID 提供运行索引；索引引用同一个槽位。
- `ExecutionControlSlot` 在挂起期间保留取消意图，每次获取运行占用时生成框架 signal 并继承取消。暂停只影响本次运行。
- 排队任务在提交前用已有执行 ID 登记，开跑只检查原槽位，不自行重建登记。
- 受理资格、运行占用和未结束子任务分别表达不同事实，不再用线程存活或子执行阶段代替它们。
- 框架源码只读，未修改依赖版本、持久化结构或前端契约。

## 停止与收尾

1. 停止先关闭根会话的登记入口，同时标记已有槽位取消。
2. 通过一次批量执行查询补齐数据库中的未结束执行，覆盖重启后的空注册表；不再逐子会话查询。
3. 释放根登记锁后调用统一取消入口。正在运行的执行由原循环收尾；没有运行占用的 CREATED / RUNNING / SUSPENDED 执行直接取消、提交检查点并走原终结链。
4. 批量摘要读取后若执行已终结，清除摘要重建的旧槽位，避免阻塞后续受理或留下幽灵子依赖。
5. 子执行先交付通知，再移除本次执行登记；同一子会话的新执行不受旧执行迟到收尾影响。

停止请求不提前释放受理资格。释放按执行 ID 校验，旧 finally 不能释放新一轮；重新受理也不会复活已取消的旧子任务。

## 保留的可靠性约束

- 冷启动后的数据库状态校验、审批未决校验、恢复请求持久化及原有恢复代际。
- 检查点提交后才释放运行占用、开放审批卡片和复查输入。
- 模型、命令审批共用运行占用互斥；释放时校验具体 signal 实例。
- 原终态事件、轮次收口、工具卡片取消与模型上下文回写链。
