# 等待子会话时的确认通知误报

- 截图右下角通知由前端把所有根执行 `EXECUTION_SUSPENDED` 直接映射成「等待你的确认」导致。根执行驻留等待子代理或协作输入也使用同一挂起事件。
- 现在只在该轮真实人工卡片可操作时通知，复用卡片形态、pending 与 allowedActions 判定。卡片回查晚到时等待就绪；恢复、终结或切换会话后取消待发确认。子代理仍在运行不会屏蔽真正的根会话审批。
- 挂起后的历史回查推迟到 Vue 状态监听处理完成后发起，避免同次状态变化作废自己的回查；卸载后不再发起延迟查询。

## 回归

- `suspensionNotification.test.ts` 覆盖无人工确认、准备中/执行中/已决/不可用卡片、三类真实卡片就绪、旧轮卡片、迟到响应、恢复与会话切换。
- `suspensionNotification.smoke.cjs` 通过真实 useChatView、SSE 解析、历史回查和桌面桥通知捕获，先验证自动驻留不通知，再用同一场景的真实卡片作正对照，验证仍能通知。
- 四组行为回退均触发失败：所有挂起直接通知、绕过卡片就绪位、移除真实视图接线、恢复会被状态监听作废的回查时序。
- 新测试接入 test、test:all；浏览器回归同时接入 test:smoke。
- `npm test` 完整回归与 `npm run build` 通过。生命周期旧用例改为按服务端实际状态回查，并在断言失败时也清理订阅。
