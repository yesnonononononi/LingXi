# 工作区读图

`read_image` 接收一个工作区内的 `path`。模型配置中的 `vision` 为 true 时，工具加工层向默认 Agent、显式 Agent、团队指挥者和成员统一补充它；为 false 时，即使 Agent 手动配置了该工具，也会移除。

工具回执只有元数据。工具轮提交后，图片在下一次模型调用前作为用户消息注入，不需要用户再发一条消息。子 Agent 按自己的实际模型判定是否开放读图。

- 支持 PNG、JPEG、GIF、BMP，按文件头识别；GIF 取首帧，GIF/BMP 转为 PNG。
- 单文件最多 10 MiB、4000 万像素；长边超过 1568 像素时等比缩小。
- 每次执行最多注入 4 张不同图片，同批调用也受此限制；相同内容不重复注入。
- 文件字节通过工作区桥接读取，目录链接不能绕过工作区边界。
- 缓存保存在 `${lingxi.data.dir}/images/<sessionId>/`，待注入队列与已注入记录随执行快照保存。缓存缺失时向模型说明图片不可用。

设置页和独立模型表单提供“支持图片输入（识图）”开关，默认关闭。只有模型及当前接口均支持图片输入时才能开启；误开启可能导致接口异常并使整轮执行失败。后台新增模型时要求显式提供 `vision`。

`model_config.vision` 由 V12 迁移补齐，旧记录默认 false。当前运行配置仍沿用既有 `models.json` 存储，表导入、JSON 保存和接口均携带此字段。模型连接与能力来自同一次配置读取，能力布尔值随执行快照固定；后续修改配置对新执行生效。工具执行时再次校验该声明，不根据模型名称或 YAML 推断。

`ToolListProcessor` 统一处理默认工具、指挥者/成员协作工具、MCP 发现入口、Skill、计划与识图工具。全部补充完成后，再按注册表只读标记和执行身份限制清单，防止补充工具绕过权限。默认工具仅由未选择 Agent 和团队的路径授予；显式 Agent 的其他配置保持原义。

验证覆盖工具边界、转码、批次预算、快照恢复、主/子执行的模型判断，以及本地模拟模型端点驱动的真实框架工具轮。模拟端点验证发送内容与时序，不代表已通过外部模型的真实识图验收。
