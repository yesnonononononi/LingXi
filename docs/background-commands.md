# 后台命令

`execute_command` 使用可选参数 `background`，默认同步执行。设为 `true` 时先保存真实的任务、会话、轮次和执行身份，再启动工作空间命令，立即返回字符串 `taskId`。安全检查、审批、沙箱、超时与输出预算仍然生效。

后台进程的运行时限使用独立配置，默认 30 分钟，最小 1 秒；修改后重启应用生效：

```yaml
lingxi:
  tools:
    command:
      background-timeout: 30m
```

`execute_command` 的 240 秒仍用于前台执行和后台提交操作；后台启动后使用上述运行时限。`manage_command` 的 30 秒只限制管理调用，不会重置后台进程的计时。

使用 `manage_command` 操作当前会话的任务：

- `{"action":"list"}`：返回最近 50 项摘要，并补齐更早的全部在途任务。
- `{"action":"snapshot","taskId":"实际任务 ID"}`：立即返回当前输出或持久化结果。
- `{"action":"read","taskId":"实际任务 ID"}`：等待完成，返回最终状态、输出、退出码和截断标记；管理调用超时中断等待，不停止后台进程。
- `{"action":"stop","taskId":"实际任务 ID"}`：等待确认停止；取消失败会报错，可重试。已自然结束的任务保留原结果。

界面仅允许删除已结束且所属执行也已结束的任务；任务记录尚承担结果通知时不能删除。通用任务接口只查询事实和转交受控删除，手工新增或修改状态会被拒绝。

默认 Agent 同时提供这两个工具；自定义 Agent 使用后台模式时，应同时选中它们。只读档位保留命令控制，命令本身仍受终端安全策略约束。

模型调用前，独立的终端拦截器会把本执行已结束任务的摘要注入上下文，不要求绑定 Agent，也不经过协作邮箱。摘要包含任务标识、终态、退出码、用途和最多 2,000 字符输出；完整已保存输出通过 `snapshot` 查询。成功、失败、超时、确认取消和状态丢失都会通知。

执行准备自然结束时，若仍有本执行的在途任务或尚未注入的结果，会保留检查点并挂起。任务终态和恢复请求同事务保存，再由现有恢复协调器唤醒；若完成早于挂起，保留唤醒会在控制槽位释放后重放。根执行和子执行都适用；同会话其他执行的任务不阻挡本次收尾。已取消或失败的执行不会因此重新启动，任务仍可从界面查询。

通知回执按任务标识保存在执行检查点中，消息压缩后仍可去重。检查点保存前发生中断或崩溃，结果允许重新投递；这不是对模型调用副作用的恰好一次保证。旧任务没有执行标识时只保留查询与控制，不推断通知接收者。

界面调用入口为 `GET /task/runtime/list?sessionId=...`、`GET /task/runtime/{id}?sessionId=...` 和 `POST /task/runtime/{id}/stop?sessionId=...`。任务标识始终使用字符串，不能转成 JavaScript `Number`。

输出由框架持续读取并限制长度；终态或恢复请求落库失败会保留原结果重试。应用正常关闭时尝试停止存活任务；重启后无法确认的在途任务标为 `LOST`，不会自动重放命令或接管原进程。执行恢复沿用现有启动收口策略，遗留的运行态与未完成恢复请求不会被自动重跑。

任务用途取自 `execute_command.intention` 并持久化，用于界面列表名称。状态写入后，经所属根会话 SSE 发送 `BACKGROUND_TASK_CHANGED` 通知；界面回查当前会话任务，进入会话和断线重连时也会回查。通知不依赖模型执行是否结束。
