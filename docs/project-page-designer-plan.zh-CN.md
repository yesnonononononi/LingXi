# 项目页面设计预览：分阶段实施与可视化验收

日期：2026-11-07。状态：待实施的设计方案；本文不代表功能已交付。

## 1. 目标与交付原则

在 LingXi 侧边栏加载用户前端项目的真实页面，允许用户在运行中的页面上修改文字和样式，实时查看效果，再导出 HTML / 图片，交给 Agent 在原项目中实现。

页面由原项目的开发服务器编译和渲染。预览编辑只改变当前页面的 DOM 与样式，不直接写回业务源文件。导出的 HTML 是当前页面状态的结构与样式参照，图片是视觉参照；Agent 结合两者和用户意见修改源码。

**每个阶段必须在界面上产生可见、可操作的变化，并能独立演示。第一阶段就必须出现用户真实项目的可交互 iframe。** 只完成接口、协议、数据结构、静态示意图或占位页面，均不算完成阶段。

每阶段单独提交。演示记录包括实际项目、启动方式、页面 URL、操作步骤、截图及限制；测试通过不替代真实界面验收。

## 2. 首轮范围与现有基础

首轮面向 Electron 桌面端、本机已启动的开发服务；阶段二起先支持可接入开发插件的 Vite 项目。Vue / React 由原项目完成渲染，Inspector 处理渲染后的 DOM。

| 已有位置 | 可以复用的能力 | 需要补充的部分 |
| --- | --- | --- |
| `frontend/src/components/chat/FilePreviewPanel.vue` | 文件标签、拖拽宽度、最大化 | 页面入口及代码 / 页面模式切换 |
| `frontend/src/views/chat/ChatView.vue` | 侧栏挂载与会话上下文 | 没有打开文件时也能打开项目页面 |
| `frontend/src/composables/useFilePreview.ts` | 现有文本文件读取与监听 | 页面连接状态单独管理，保留原有文件逻辑 |
| `frontend/electron/file-preview.cjs` | 主进程来源校验、真实工作区解析的参考 | 不复用会截断内容的文本读取来渲染网页 |
| `frontend/src/types/chatInputCommands.ts` | 设置输入文本、批量图片附件 | 设计稿交付与绑定目标会话 |
| `frontend/src/services/agent.ts` | 文字及图片提交 | 首版通过真实设计稿路径传递 HTML |
| `frontend/src/views/chat/useChatSending.ts` | 受理与执行状态 | 执行中保留设计意见草稿，空闲后发送 |

第一阶段直接连接 URL，不要求安装 Inspector，不依赖 HTML 导出，也不要求 Agent 参与。

自动启动开发服务器、远程工作区端口转发、任意网站代理、通用构建工具适配、布局拖拽、源码映射及直接回写，均列为后续增强。

## 3. 页面接入方式

### 3.1 用户配置与页面来源

页面 URL 是用户指定的真实地址，例如 `http://localhost:5173/settings/profile?tab=theme`；地址属于示例，不是已检测到的服务。

用户先用项目原有方式启动服务，在 LingXi 输入完整 URL 后打开。页面继续使用原路由、组件树、全局样式、接口代理和业务数据。也可以先打开首页，在 iframe 中进入目标页面。

文件路径与页面地址是不同概念。`.vue` / `.tsx` 文件可能依赖父组件、路由参数及登录状态，首轮不把源文件强行转换成独立页面，也不推断一个文件必然对应一个路由。

本轮 URL 仅接受 HTTP / HTTPS、本机回环地址及明确端口；禁止内嵌账号密码及其他协议。URL 输入保留路径、查询参数与 hash。用户提交的地址与页内实际导航地址分开记录；跨域时不能假装父页面已读到最新地址。

连接配置绑定现有真实工作区及会话。用户填写的 URL 是连接配置，不是系统已经验证的项目归属事实；不能仅凭端口推断工作区。会话不存在时走标准创建流程，不构造临时会话或工作区实体。

### 3.2 显示页面与接入编辑分开

阶段一让 iframe 直接加载开发服务 URL。阶段二在目标开发页面内注入 Inspector，由它操作 DOM，通过消息把结果交给 LingXi。

优先使用 Vite 开发插件注入，保留原项目编译配置及资源加载方式。允许显式增加开发期插件配置，但页面编辑不写入业务源文件。插件只在设计预览启动方式下启用，不进入生产构建；接入方式需在阶段二交付时演示。

页面可展示但未接入 Inspector 时，仍可以浏览，界面明确显示“尚未连接编辑能力”。编辑握手失败不应阻断阶段一的浏览功能。

### 3.3 接入前提与失败边界

| 情况 | 产品行为 |
| --- | --- |
| 开发服务未启动、端口错误、TLS 错误 | 展示已确认的诊断，保留地址并提供重试；浏览器可提供的信息不足时明确说明 |
| 页面禁止 iframe 嵌入 | 提示检查开发环境的 `X-Frame-Options` / CSP `frame-ancestors`，不关闭全局浏览器安全限制 |
| 页面依赖 API 或登录 | 沿用项目原有服务和登录流程；iframe 外的登录状态不保证自动共享 |
| OAuth 弹窗、顶层跳转、第三方 Cookie | 列为特定登录流程的兼容项，不承诺所有认证方式首轮可用 |
| 服务在容器或远程主机 | 必须先有桌面端可访问的地址；本轮不自动打通网络或转发端口 |
| 组件重新渲染、热更新、路由切换 | 使对应节点引用失效，按阶段三的草稿规则处理 |

父页面跨域读取 iframe DOM 与接口 CORS 是不同限制。给 API 开启 CORS 不能解决页面嵌入或元素检查问题。

## 4. 阶段总览

以下为开发估算，按熟悉项目的一名开发者计算，包含阶段验证，不包含解决用户项目自身的安装、接口及认证故障。各行是增量人日；以验收结果推进，不按估算天数宣布完成。

| 阶段 | 用户新增可见能力 | 增量估算 | 阶段结束时能否独立使用 |
| --- | --- | --- | --- |
| 一：真实页面浏览 | 打开预览框，在 iframe 中操作项目页面 | 1–2 人日 | 可以作为项目页面预览使用 |
| 二：元素检查 | 悬停高亮、双击选择、查看样式 | 1–2 人日 | 可以定位并查看设计属性 |
| 三：实时设计 | 改文字与常用样式，撤销及重置 | 2–3 人日 | 可以在真实页面上试调设计 |
| 四：导出设计稿 | 导出 HTML 和区域 PNG | 2–4 人日 | 可以独立交付设计参照 |
| 五：交给 Agent | 设计稿、截图与意见进入现有会话 | 1–2 人日 | 形成项目修改闭环 |

合计约 7–13 人日。自动启动服务、全页长截图及复杂资源导出另行估算。第一阶段可以先交付并收集反馈，不必等待其余阶段。

## 5. 阶段一：真实项目页面进入可交互 iframe

### 用户能看到的界面

```text
┌──────────────────── 项目页面预览 ────────────────────┐
│ [文件] [项目页面]                      [最大化] [关闭] │
│ 地址 [http://localhost:5173/settings      ] [打开]      │
│ [重新加载]  浏览模式 · 编辑能力尚未接入                  │
├───────────────────────────────────────────────────────┤
│                                                       │
│             用户原项目渲染的真实页面                    │
│          可以点击、输入、滚动、切换页面                  │
│                                                       │
└───────────────────────────────────────────────────────┘
```

### 改造范围

- `ChatView.vue` 与侧栏外壳增加项目页面入口；零个文件标签时也能打开预览。不得为了满足文件面板条件创建虚假文件标签。
- 新增独立 `ProjectPagePreview.vue`、`useProjectPagePreview.ts` 和页面预览类型，管理 URL、加载尝试及重新加载。文件标签仍使用现有类型，不添加虚假的文件路径、监听键或后端实体。
- 保留文件预览布局和现有读取行为；预览区沿用拖拽与最大化，聊天列宽继续使用现有单一真源。
- iframe 初次打开后，隐藏面板或切换文件 / 页面模式保持实例，避免丢失输入及登录状态；明确关闭、切换会话或工作区时销毁实例，隔离业务页面状态。
- 默认限制顶层导航、弹窗及下载，不给页面 Node / Electron 能力。嵌入策略需要允许项目运行所需的脚本、表单及独立页面 origin；不能将用户页面注入 LingXi 主页面的权限域。
- 失败诊断优先复用或补充限定目标 frame 的 Electron 事件。主进程入口验证主窗口主 frame，不能仅检查 `event.sender`。

加载状态只表达“正在尝试加载 / 加载等待超时 / 已收到页面加载事件 / 已确认失败”。iframe `load` 事件或 HTTP 200 均不等于业务页面正常；阶段一的业务可用性由实际操作验收。没有诊断证据时不编造具体失败原因。

### 演示与验收

1. 使用一个用户已有的真实项目，记录工作区、启动命令、URL 与目标路由；不是新生成的演示 HTML。项目应先在浏览器中能正常运行。
2. 不打开任何文件，在 LingXi 打开项目页面预览并输入地址，看到真实项目内容。
3. 点击项目中的按钮、输入文字、滚动页面、完成一次项目自身的路由跳转；相关 CSS、图片及测试所需接口正常加载。
4. 切换文件 / 页面模式后，刚输入的内容仍在；拖拽宽度与最大化可用。
5. 重新加载恢复页面正常初始化行为。明确关闭再打开、切换工作区时，不泄漏上一个页面的输入和业务状态。
6. 用一个未监听端口验证重试与等待超时提示；用禁止嵌入的对照页面验证问题说明。超时后迟到的结果不能覆盖新地址的状态。
7. 在桌面实际运行或打包产物中完成验收；仅在 Vite 浏览器开发模式通过不够。

**通过标准：用户能在 LingXi 内操作自己的项目页面。此阶段没有选元素、样式编辑和导出按钮，也不要求 Inspector 握手成功。**

## 6. 阶段二：元素选中与样式面板

### 可见变化

工具栏新增“浏览 / 选元素”。选元素模式下，悬停显示边框，双击锁定目标并弹出属性面板；用户可以选择父元素。切回浏览模式恢复原页面交互。

面板展示字体、字号、字重、行高、文字色、背景色、四向 margin / padding、边框与圆角，以及当前元素尺寸。计算值与源码声明区分，不能把计算出的 px 值标成源文件原值。

### 改造与约束

- 新增 Inspector 运行脚本、Vite 开发接入及宿主通信桥；面板状态与页面运行逻辑分开。
- 选择模式提前拦截点击和表单等默认操作，不能等到 `dblclick` 才拦截已经发生的业务动作。
- 使用协议版本、请求标识、页面代次区分消息。校验来源 origin、目标 frame、消息类型及载荷；连接标识只用于关联，不作为可信权限凭证。
- 页面只报告检查与编辑结果，不能通过消息调用任意文件操作或自动发起 Agent 请求。
- 首轮支持普通 DOM 与可访问的开放 Shadow DOM；嵌套跨域 iframe、封闭 Shadow DOM、canvas 内部对象标明边界。

### 演示与验收

1. 同一真实项目接入插件后看到“编辑能力已连接”；没有插件时仍可浏览。
2. 双击一个按钮内部文字，看到正确边框及属性，能向上选到按钮容器。
3. 选择操作不触发按钮业务逻辑；浏览模式下按钮恢复正常。
4. 滚动、调整视口后选框位置正确；路由切换后旧选中状态失效。
5. 来自其他 frame、旧页面代次或错误 origin 的消息不能改变当前选中状态。

## 7. 阶段三：实时修改文字与样式

### 可见变化

属性面板变为可编辑。调整字号、颜色、间距和圆角立即更新真实页面；双击文字进入编辑，确认后更新文本。工具栏出现“撤销 / 重做 / 重置”和“预览草稿”提示。

### 改造与约束

- 新增独立草稿状态与操作历史，记录目标、修改前后值、CSS 优先级及页面代次。
- 文字编辑定位文本节点，保留同一元素内的图标、链接及其他子节点；复杂富文本首轮明确限制。
- 样式仅接受白名单属性与合法值；合并连续滑动产生的操作，避免一次撤销只退回一个像素。
- 普通 DOM 重新渲染后，只有能确认同一目标时才重新应用。不能唯一定位就显示失效，禁止套用到另一个相似按钮。
- 路由切换或重新加载使旧代次草稿失效，用户可先导出后重置；不承诺自动跨路由恢复。手动临时编辑不触发 HMR，也不写入原项目文件。
- 隐藏面板保留草稿；明确关闭、导航、切换会话或工作区前，有草稿时提供导出或放弃入口。

### 演示与验收

1. 在阶段二的按钮上改文字、字号、颜色、padding 和圆角，立即看到变化。
2. 连续撤销及重做恢复对应效果，按钮图标和链接仍在。
3. 触发项目重渲染，目标无法确认时出现失效提示，不污染其他元素。
4. 重置并重新加载后回到原项目效果；用修改前后文件摘要证明业务源文件未被编辑器写入。

## 8. 阶段四：HTML 与图片导出

### 可见变化

新增“导出 HTML / 框选截图”。用户框选区域后看到 PNG 预览；导出 HTML 成功后显示真实保存位置及资源完整性结果。

### 导出契约

- HTML 基于编辑后的当前 DOM，携带必要样式与资源，移除 Inspector 节点及原应用启动脚本，避免重新执行后覆盖设计效果。
- 默认导出当前视口状态的静态参照。视口宽高随稿记录；不声称保存原组件事件、应用状态逻辑或所有响应式断点。
- 保留可读 HTML 结构与 CSS，处理伪元素、图片、字体和表单当前值。密码与敏感输入不导出。
- 资源优先内嵌；无法内嵌时保存为 `design.html` 与相邻资源目录。跨域样式表不能假定可从 CSSOM 读取，受限资源要显式报告，不悄悄产出缺资源的“成功”文件。
- 首轮以普通 DOM 页面为验收范围；canvas、视频、封闭 Shadow DOM 等视觉内容有边界时显示具体限制，并保留截图作为补充。
- PNG 使用 Electron 原生页面捕获，首轮支持可见区域及框选区域。截图前隐藏选框、工具栏等编辑浮层，完成后恢复。
- 坐标转换包含 iframe 位置、滚动、预览缩放及实际截图比例。首轮不包含整页滚动拼接。
- 主进程保存校验来源、目标工作区、真实路径与覆盖确认；预览页不能指定任意宿主路径。导出失败不清除草稿。

### 演示与验收

1. 导出修改后的真实项目页面，打开保存的 HTML，在同一视口核对文字、间距、颜色、圆角、图片及字体。
2. 关闭原开发服务后重新打开导出稿，已声明完整的资源仍能展示；缺资源时必须能看到导出限制说明。
3. 100% 与至少一种非 100% 系统显示缩放下框选同一区域，截图边界正确且不含编辑浮层。
4. 导出不重复执行项目业务请求；失败、取消及覆盖文件时草稿仍可继续编辑。

## 9. 阶段五：设计稿与意见交给 Agent

### 可见变化

导出后出现“交给 Agent 实现”。用户填写意见，在发送前看到设计稿位置、截图、原页面地址和修改摘要，提交后进入现有会话。

### 改造与约束

- HTML 与资源导出到当前真实工作区中 Agent 可读取的位置，以已确认存在的路径引用；PNG 走既有图片附件限制。
- 路径通过主进程写入成功的回执产生，不把客户端拼接路径当成已导出事实。远程 Agent 无法访问宿主文件时明确阻止此交付方式，后续另做上传契约。
- 请求包含原项目页面地址、视口、导出时间、设计稿路径、图片、修改摘要及用户意见；页面文本作为参考数据，不提升为系统指令。
- 复用现有用户消息受理及会话事件流，不另建执行通道。原会话执行中保留草稿，待空闲再提交，不自动中断或插入运行中的执行。
- Agent 实现是一次新的源码修改；预览编辑器不自动把设计稿 HTML 覆盖到组件文件。完成后清除临时设计覆盖，重新加载项目页面供用户对比。

### 演示与验收

1. 从实际导出稿填写一条局部修改意见，发送后用户消息包含正确设计稿引用及截图。
2. Agent 能读取文件并在原项目修改；重新加载原页面后，清除临时覆盖仍能看到实现效果。
3. 运行中提交、导出失败、路径不可读或附件超限均不丢意见，不显示虚假的发送成功。

## 10. 实施边界与验证纪律

### 模块边界

组件与文件名为实施建议，不要求提前搭建空模块。各阶段只增加本阶段能使用的能力。

| 模块 | 负责内容 | 首次引入 |
| --- | --- | --- |
| 页面预览组件与 composable | 页面入口、URL、iframe 生命周期 | 阶段一 |
| Electron 页面诊断与受限通信 | 确认 frame、错误诊断；后续捕获与保存 | 阶段一按需，阶段四扩展 |
| Inspector 与 Vite 插件 | DOM 选择、属性读取、页面内编辑 | 阶段二 |
| 属性面板与草稿状态 | 试调、撤销、重做、失效处理 | 阶段三 |
| 导出协作模块 | HTML、资源、PNG 和真实保存回执 | 阶段四 |
| 设计意见提交 | 组装参考与复用现有聊天发送 | 阶段五 |

首轮不新建数据库模型，不改 Harness 框架，不重构既有文件预览或聊天发送体系。若实施发现现有契约无法表达实际需要，应明确补齐契约，不用临时假实体兜底。

自动启动服务单独增强：管理工作目录、命令、端口、就绪、日志、停止和退出清理。现有后台命令与 Agent 执行生命周期有关，不能直接把长期开发服务器放进去后宣称接入完成。

### 每阶段验收与提交

- 交付顺序为一至五；前阶段可演示后再进入下一阶段。每阶段附实际界面截图或短录屏、真实项目复现步骤、验证结果及已知限制。
- 新增回归用例显式接入 `frontend/package.json` 的测试入口。按阶段验证 URL 与隔离、旧消息失效、撤销、导出坐标及发送失败等实际行为。
- 为关键回归做非等价变异，证明撤去保护时用例变红；“接口存在”“组件被渲染”不能替代 iframe 内的实际交互验证。
- 任何“不存在残留”“没有源文件修改”等扫描结论，先做故意含目标特征的金丝雀正对照，并确认完整覆盖；源文件未修改同时比较明确文件集合的前后摘要。
- 保留他人工作树改动，每阶段只提交本阶段文件；不借机调整无关布局、依赖或框架。
