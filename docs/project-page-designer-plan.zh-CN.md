# 项目页面设计预览：基于 Glide 的分阶段实施与可视化验收

创建日期：2026-11-07。修订日期：2026-11-08。状态：阶段一已有实现与交付记录；Glide 接入及后续阶段待实施。本次修订只调整开发方案，不代表 Glide 已接入。

## 1. 目标与交付原则

在 LingXi 侧边栏加载用户前端项目的真实页面，复用 Glide 画布、元素检查和属性编辑，允许用户修改文字与样式，直接写回当前项目源码，并通过项目自身热更新或重新加载查看结果。复杂修改可附图片和意见交给现有 Agent。

首版贴合 Glide 的原有设计，采用 Live / Instant 源码回写流程。页面内的即时更新用于交互反馈，服务端回执及实际文件内容才是写入成功的依据；刷新后仍应展示修改后的结果。暂不自建只改 DOM 的设计草稿体系，不把源码定位与编辑链路拆开重做。

**HTML 导出暂缓，不作为任何首版阶段的交付门槛。** 图片导出优先复用 Glide 现有能力；区域截图、复杂资源打包等增强后续再做。Agent 直接操作原项目，不再依赖一份中间 HTML 设计稿。

**每个阶段必须在界面上产生可见、可操作的变化，并能独立演示。第一阶段就必须出现用户真实项目的可交互 iframe。** 只完成接口、协议、数据结构、静态示意图或占位页面，均不算完成阶段。

每阶段单独提交。演示记录包括实际项目、启动方式、页面 URL、操作步骤、截图及限制；测试通过不替代真实界面验收。

## 2. 首轮范围与现有基础

首轮面向 Electron 桌面端、本机已启动的 Vite 项目。Vue / React 由原项目完成渲染，Glide 负责代理、页面检查与源码回写；框架支持声明不替代真实项目验证。

### Glide 引入基线

- 上游仓库：[SrivarsanK/Glide](https://github.com/SrivarsanK/Glide)。已审查源码提交：`c4d559a8e102087c2c984bcc640d7b207dfcac08`，该提交根包版本 `1.1.2`，仓库标注 `Apache-2.0`。
- 实施以该提交作为可复现基线，不跟随浮动分支或 `latest`。落实为固定版本的适配副本，保留上游来源、许可证与修改记录；具体落盘目录在阶段二确定。
- 优先以独立本地 Node 服务承载 Glide 完整编辑器，嵌入现有侧栏；不先将其界面拆成 Vue 组件，也不重新实现一套 Inspector、属性面板和源码写入器。
- 2026-11-08 的源码评估中，画布、桥接、暂存等 7 个测试文件的 45 项测试通过；这不代表已通过 LingXi 集成或真实用户项目验收。

## 3. 页面接入方式

### 3.1 用户配置与页面来源

页面 URL 是用户指定的真实地址，例如 `http://localhost:5173/settings/profile?tab=theme`；地址属于示例，不是已检测到的服务。

用户先用项目原有方式启动服务，在 LingXi 输入完整 URL 后打开。页面继续使用原路由、组件树、全局样式、接口代理和业务数据。也可以先打开首页，在 iframe 中进入目标页面。

文件路径与页面地址是不同概念。`.vue` / `.tsx` 文件可能依赖父组件、路由参数及登录状态，首轮不把源文件强行转换成独立页面，也不推断一个文件必然对应一个路由。

已有直接浏览入口接受 HTTP / HTTPS、本机回环地址及明确端口。Glide 首版编辑入口先支持本机 HTTP 开发服务；HTTPS 代理等能力需另行验证，不能沿用浏览入口的支持范围作承诺。禁止内嵌账号密码及其他协议，保留路径、查询参数与 hash。

用户提交的项目地址、Glide 服务地址、代理后的内部页面地址分别记录。上游 `loadApp` 从绝对 URL 提取路径和查询参数，实际目标端口来自服务配置；适配时必须同步端口并补齐 hash，不能让地址栏指向一个服务、实际却加载另一个服务。

连接配置绑定现有真实工作区及会话。用户填写的 URL 是连接配置，不是系统已经验证的项目归属事实；不能仅凭端口推断工作区。会话不存在时走标准创建流程，不构造临时会话或工作区实体。

### 3.2 保留直接浏览，新增 Glide 编辑通道

```text
用户原有开发服务（继续负责组件、路由、样式和接口）
                  ↓
Glide 本地服务（代理 / 注入桥接 / 源码检查与回写）
                  ↓
LingXi 侧栏的 Glide 编辑器 iframe
                  ↓
Glide 内部 iframe 展示原项目，选择元素并实时修改
                  ↓
Glide 回写真实源码 → 原项目 HMR 或重新加载
```

阶段二先复用 Glide 代理注入，不再开发自有 Vite Inspector 插件。可靠回写需要源码定位：优先复用上游 `glideSourceStamping` 开发插件，按实际框架接入；代理能选中 DOM 不等于一定能定位其源码。没有可靠定位的元素只检查、不写入，并显示具体原因。

开发插件只在开发配置启用，不进入生产构建。Glide 启动器及索引写入等副作用应列明文件与位置，不自动安装 AI skill，不修改用户编辑器配置。

上游编辑器根响应使用 `X-Frame-Options: SAMEORIGIN`。适配副本需要允许实际 LingXi 宿主嵌入，同时维持编辑器与内部代理页所需的访问关系。变更仅限受控本地 Glide 服务，不关闭 Electron 全局 `webSecurity`。上游代理会处理目标页面的嵌入头，首版仅对用户明确连接的本地开发服务使用这条能力。

阶段一直接浏览仍可独立使用。Glide 未启动或编辑连接失败时，显示明确状态并保留浏览入口；不得把失败描述成源码已写入。

### 3.3 接入前提与失败边界

| 情况 | 产品行为 |
| --- | --- |
| 开发服务或 Glide 服务未启动、端口错误 | 区分是哪一层失败，保留地址并提供重试；信息不足时明确说明 |
| 页面禁止 iframe 嵌入 | 直接浏览保持原有诊断；Glide 通道验证受控代理和编辑器嵌入策略，不关闭全局浏览器安全限制 |
| 页面依赖 API 或登录 | 沿用项目原有服务和登录流程；iframe 外的登录状态不保证自动共享 |
| OAuth 弹窗、顶层跳转、第三方 Cookie | 列为特定登录流程的兼容项，不承诺所有认证方式首轮可用 |
| 服务在容器或远程主机 | 必须先有桌面端可访问的地址；本轮不自动打通网络或转发端口 |
| 组件重新渲染、热更新、路由切换 | 刷新定位和文件版本；过期目标重新选择，不按旧坐标继续写入 |
| 文件被 Agent、编辑器或其他进程修改 | 按实际摘要拒绝过期写入及不安全撤销，不覆盖外部改动 |

父页面跨域读取 iframe DOM 与接口 CORS 是不同限制。给 API 开启 CORS 不能解决页面嵌入或元素检查问题。

## 4. 阶段总览

以下为开发估算，按熟悉项目的一名开发者计算，包含阶段验证，不包含用户项目自身故障及上游复杂兼容问题。阶段一保留原交付记录；二至五为采用 Glide 后的增量工作，以验收结果推进。

| 阶段 | 用户新增可见能力 | 增量估算 | 阶段结束时能否独立使用 |
| --- | --- | --- | --- |
| 一：真实页面浏览 | 打开预览框，在 iframe 中操作项目页面 | 已有实现记录 | 保留现有浏览能力 |
| 二：Glide 接入与原生编辑 | 看到 Glide 画布，选择元素、改文字和样式并写回源码 | 1–2 人日 | 可以完成一次真实页面修改 |
| 三：回写与历史验证 | 热更新、重新加载、撤销和重做均与文件一致 | 1–2 人日 | 可以持续编辑并确认结果 |
| 四：图片导出 | 从当前页面导出图片并查看结果 | 1–2 人日 | 可以交付视觉参照 |
| 五：交给 Agent | 图片、源码线索与意见进入现有会话 | 1 人日 | 可以由 Agent 接续复杂修改 |

剩余工作粗估 4–7 人日，阶段二的真实项目验证后重新校准。HTML 导出、独立预览草稿及自研整套编辑器均不计入本轮。阶段二本身就是下一次可视化交付，不必等待图片或 Agent 集成。

## 5. 阶段一：真实项目页面进入可交互 iframe

本节保留原直接浏览阶段的实现目标与验收口径，历史交付记录见第 11 节。本次文档修订不重跑或重判该阶段；Glide 接入需复验既有浏览、布局和状态机行为，不重新从零实现。

### 用户能看到的界面

```text
┌──────────────────── 项目页面预览 ────────────────────┐
│ [文件] [项目页面]                      [最大化] [关闭] │
│ 地址 [http://localhost:5173/settings      ] [打开]      │
│ [重新加载]  浏览模式 · 编辑能力尚未接入                  │
├───────────────────────────────────────────────────────┤
│                                                       │
│             用户原项目渲染的真实页面                    │
│          可以点击、输入、滚动、切换页面                  │
│                                                       │
└───────────────────────────────────────────────────────┘
```

### 改造范围

- `ChatView.vue` 与侧栏外壳增加项目页面入口；零个文件标签时也能打开预览。不得为了满足文件面板条件创建虚假文件标签。
- 新增独立 `ProjectPagePreview.vue`、`useProjectPagePreview.ts` 和页面预览类型，管理 URL、加载尝试及重新加载。文件标签仍使用现有类型，不添加虚假的文件路径、监听键或后端实体。
- 保留文件预览布局和现有读取行为；预览区沿用拖拽与最大化，聊天列宽继续使用现有单一真源。
- iframe 初次打开后，隐藏面板或切换文件 / 页面模式保持实例，避免丢失输入及登录状态；明确关闭、切换会话或工作区时销毁实例，隔离业务页面状态。
- 默认限制顶层导航、弹窗及下载，不给页面 Node / Electron 能力。嵌入策略需要允许项目运行所需的脚本、表单及独立页面 origin；不能将用户页面注入 LingXi 主页面的权限域。
- 失败诊断优先复用或补充限定目标 frame 的 Electron 事件。主进程入口验证主窗口主 frame，不能仅检查 `event.sender`。

加载状态只表达“正在尝试加载 / 加载等待超时 / 已收到页面加载事件 / 已确认失败”。iframe `load` 事件或 HTTP 200 均不等于业务页面正常；阶段一的业务可用性由实际操作验收。没有诊断证据时不编造具体失败原因。

### 演示与验收

1. 使用一个用户已有的真实项目，记录工作区、启动命令、URL 与目标路由；不是新生成的演示 HTML。项目应先在浏览器中能正常运行。
2. 不打开任何文件，在 LingXi 打开项目页面预览并输入地址，看到真实项目内容。
3. 点击项目中的按钮、输入文字、滚动页面、完成一次项目自身的路由跳转；相关 CSS、图片及测试所需接口正常加载。
4. 切换文件 / 页面模式后，刚输入的内容仍在；拖拽宽度与最大化可用。
5. 重新加载恢复页面正常初始化行为。明确关闭再打开、切换工作区时，不泄漏上一个页面的输入和业务状态。
6. 用一个未监听端口验证重试与等待超时提示；用禁止嵌入的对照页面验证问题说明。超时后迟到的结果不能覆盖新地址的状态。
7. 在桌面实际运行或打包产物中完成验收；仅在 Vite 浏览器开发模式通过不够。

**通过标准：用户能在 LingXi 内操作自己的项目页面。此阶段没有选元素、样式编辑和导出按钮，也不要求 Inspector 握手成功。**

## 6. 阶段二：Glide 接入与原生编辑

### 可见变化

在已有项目页面区打开 Glide 完整编辑器，看到画布、元素高亮、属性面板、缩放和设备尺寸。使用上游 Preview 模式操作项目，回到设计模式选择元素，修改文字、字号、颜色、间距与圆角。

首版采用上游 Live / Instant 模式，明确显示“修改直接写入源码”。选择手势、面板布局和属性编辑尽量沿用 Glide，不为复刻原设想的浮动菜单重做界面。源码修改后由项目自身更新页面；未启用 HMR 时提供重新加载，不宣称已自动更新。

### 改造与约束

- 复用上游代理、桥接、画布、属性面板、源码映射、事务写入和文件版本校验。保留必要的适配副本，不先拆分整个上游模板。
- Electron 管理 Glide 启动、固定项目根、目标端口、就绪、错误日志、停止及退出清理。用户项目开发服务仍由用户启动；两类进程生命周期分开。
- 每个编辑连接绑定真实会话和工作区；旧连接不能继续修改新工作区。原有主进程诊断适配两层 iframe，不能把编辑器加载成功当作内部项目加载成功。
- 校验宿主消息 origin、具体 frame、协议、页面代次和载荷；保留上游服务身份校验和真实路径边界。用户操作只针对已连接工作区，项目页面不获得 Electron / 任意宿主文件权限。
- 没有有效源码映射或文件摘要时明确拒绝写入，不用 DOM 克隆或临时文件伪造成功。首版样板项目接入上游开发期源码标记插件。
- 首轮验证普通 DOM；开放 Shadow DOM、嵌套跨域 iframe、封闭 Shadow DOM、canvas 内部对象等按实际能力列明，不把上游框架支持列表当作验收证据。

### 演示与验收

1. 在 LingXi 侧栏看到 Glide 及同一个真实项目页面，Preview 模式下点击、输入、滚动、路由跳转可操作。
2. 设计模式下选择按钮，看到正确边框及属性；选择本身不触发按钮业务动作。
3. 修改一次文字及一个样式属性，服务端确认写入，原项目文件有对应差异；重新加载后修改仍在。
4. 核对实际目标端口、深层路径、query 及 hash；滚动和调整视口后选框正确。
5. 无源码映射时显示原因并拒绝写入；来自其他 frame 或旧连接的消息不能改当前项目。
6. 实际 Electron 中验证两层 iframe、侧栏最大化、已有文件预览和关闭后的进程清理。

**通过标准：用户能在 LingXi 中用 Glide 修改真实项目，并在文件和重新加载后的页面中看到同一结果。此阶段不要求 HTML 或图片导出，也不要求 Agent 参与。**

## 7. 阶段三：源码回写、历史与冲突验证

### 可见变化

在阶段二基础上，用户能继续多次修改，通过 Glide 历史撤销和重做，并看到源码及页面同步。写入失败、定位过期或外部文件变化时，界面给出明确反馈。

### 改造与约束

- 使用 Glide 原生写入与历史服务，验证摘要、事务回执和 HMR 后目标重定位；不另建一套只管理 DOM 的撤销体系。
- 确认文字写回保留图标、链接与模板结构；动态表达式、翻译文案和共享组件必须显示实际作用范围，不把实例编辑伪装成仅影响一个实例。
- 源码回执失败后纠正乐观页面效果，必要时重新加载。路由或 HMR 后旧目标失效时要求重新选择，不按旧行号继续写。
- 历史撤销属于真实文件操作。出现用户编辑器、Agent 或其他进程的外部改动时，拒绝不安全的整文件恢复，保留现有改动；不能用重置工作树来实现“撤销”。
- 首版界面固定 Live / Instant 路径，暂不开放 Staged 模式切换。上游暂存文字丢弃后不恢复的问题已做隔离复现；若后续开放暂存，必须先补齐恢复及回归，不把“暂存”解释成所有操作均不写文件。
- 隐藏面板可保持连接；明确关闭或切换工作区时等待在途写入返回或报告其状态，不因销毁界面丢失操作回执。

### 演示与验收

1. 连续修改文字、字号、颜色、padding 和圆角，逐次确认源码差异与实际页面一致。
2. 撤销、重做后检查文件内容及重新加载后的效果，按钮图标、链接、模板表达式仍符合预期。
3. 外部修改文件后尝试过期写入和历史撤销，明确报告冲突并保留外部改动。
4. HMR、路由切换及文件内容变动后，旧目标不会误写另一个元素；需要重选时显示原因。
5. 写入失败、断线重连或操作进行中关闭窗口，结果可对账，不把尚未确认的操作显示为成功。

## 8. 阶段四：复用图片导出

### 可见变化

沿用 Glide 图片导出入口，用户可以导出选中元素或当前画布图片，看到实际保存位置并打开核对。HTML 导出、自由框选区域与整页滚动拼接均不作为首版要求。

### 导出契约

- 首版以 PNG 为验收格式。先验证 Glide 的 DOM / SVG 栅格化导出；其 PNG、JPG、SVG、PDF 入口不代表已有独立 HTML 设计稿导出。
- 核对图片、字体、背景、伪元素及跨域资源。无法正确导出时明确显示失败或限制，不声称已生成保真图片。
- 若实际样板项目无法满足基本 PNG 效果，再在本阶段补 Electron 原生截图作为明确的替代实现；不提前重建整套导出体系。
- 图片应来自服务端确认后的页面状态，导出时隐藏检查边框及编辑浮层，不把未确认的乐观修改当作已落地结果。
- 宿主保存和下载入口校验来源、真实路径与覆盖确认，不给用户项目任意宿主文件写入权限。

### 演示与验收

1. 导出已修改项目的一个元素和当前画布，打开 PNG，核对文字、颜色、间距、背景与图片。
2. 在原尺寸和一个画布缩放比例下核对范围及比例，不含检查边框与编辑浮层。
3. 资源受限、失败、取消及覆盖文件时显示真实结果，不影响已经写入的源码。
4. 不要求生成 `design.html` 或资源包；缺少 HTML 导出不阻断本阶段交付。

## 9. 阶段五：图片与源码意见交给 Agent

### 可见变化

编辑器增加“交给 Agent 继续修改”入口。用户填写更复杂的设计意见，发送前看到可选图片、原页面地址、相关源码线索及已完成的修改摘要，提交后进入现有会话。

### 改造与约束

- Agent 基于已修改的真实项目继续工作，不要求导出或读取中间 HTML。PNG 沿用既有图片附件及数量限制；没有图片时仍可提交文字和源码线索。
- 请求包含原项目地址、目标工作区、已确认写入的文件与修改摘要、可选图片及用户意见。源码定位是线索，Agent 修改前仍读取当前文件；页面文本作为参考数据，不提升为系统指令。
- 复用现有消息受理与事件流，不另建执行通道。提交前完成在途 Glide 写入；原会话执行中保留意见草稿，待空闲再提交。
- Agent 修改同一项目期间，Glide 保持浏览但暂停新的源码写入，宿主和写入服务共同约束，不能只禁用面板按钮。执行终态后刷新源码摘要与页面再恢复编辑，避免两方同时覆盖同一文件；其他编辑器造成的变化仍由版本校验处理。
- Agent 完成后按项目 HMR 或重新加载展示真实结果，不用临时 DOM 覆盖制造完成效果。

### 演示与验收

1. 手动完成一次源码修改，再提交一条布局优化意见，用户消息包含正确项目、文件线索及可选图片。
2. Agent 基于当前文件继续修改；重新加载页面后仍能看到结果。
3. Agent 执行期间浏览可用，Glide 不继续写入；执行终态后定位与文件摘要更新再恢复编辑。
4. 运行中提交、写入未完成或附件超限均不丢意见，不显示虚假的发送成功；不依赖 HTML 导出。

组件与文件名为实施建议，不要求提前搭建空模块。各阶段只增加本阶段能使用的能力。

- 交付顺序为一至五；前阶段可演示后再进入下一阶段。每阶段附实际界面截图或短录屏、真实项目复现步骤、验证结果及已知限制。
- 新增回归用例显式接入 `frontend/package.json` 的测试入口。按阶段验证嵌入、真实回写、文件冲突、撤销、图片结果及发送失败等实际行为。上游自带测试不能替代 LingXi 的两层 iframe 与真实项目集成验证。

- 保留他人工作树改动，每阶段只提交本阶段文件；不借机调整无关布局、依赖或框架。
