# 桌宠 v4 资产（v3 + wink）

v4 不是一次重画，而是 **在 v3 上追加一档**：`v4 = v3 的 8 档表情 + 1 张新母版 E9_wink`。
新增的唯一母版是 **单眼眨眼（wink）**；除此之外 v4 不引入任何新的像素资产。

## 一句话口径

| 项 | 结论 |
| --- | --- |
| v4 里新增的图 | **只有 1 张**：`expr/E9_wink.png`（2048×3072，整头贴片） |
| 其余表情档位 | **一律沿用 v3**（`../v3/expr/E1_default.png` … `E8_sleepy.png`），由构建脚本直接从 v3 裁切成 `face/<id>@1x/@2x.webp`，**不在 v4 里重复交付副本** |
| 画布 / 锚点 | 与 v3 完全一致：`2048×3072`、`anchor = (1024, 2908)`；v4 里没有任何缩放、重新居中或补边 |
| 为什么不再画整头 | 脸层（`face`，z=32，rect=`560,1064,792,400`）只吃这一块矩形；新增表情只需保证这块矩形内正确，整头重绘是纯粹的返工风险 |
| v3 可改性 | **不可改**。v3 是历史交付，`sha256` 被 v4 的 `sources[]` 引用；v3 目录零改动 |

> 任务书里写「其余 7 档由构建脚本从 v3 裁切」。我按实测口径对齐成 **E1–E8 共 8 档沿用 v3**（neutral / blink / surprised / sad / angry / shy / happy / sleepy）+ **1 档新增 wink = 9 档**；`manifest.json.expressionIds` 就是这 9 个。若构建脚本只认 7 档，请以 `expressionIds` 为准调整，不要删档。

## 怎么跑

```bash
# 重新生成 E9（幂等；同一 v3 输入必得同一 sha256）
node docs/assets/desktop-pet/v4/tools/build-wink.mjs

# 门禁校验（全绿才可入库；任一条失败退出码 1）
node docs/assets/desktop-pet/v4/tools/check-wink.mjs

# 变异自检：可把 --wink= 指向任意候选图，不会碰正式交付物
node docs/assets/desktop-pet/v4/tools/check-wink.mjs --wink=D:/tmp/candidate.png
```

三个脚本都是**纯 Node、零依赖**（自带 PNG 编解码），不需要 `npm install`；这与 v3 `tools/` 依赖 `sharp`/`ag-psd` 的做法不同，是为了让门禁在任何环境都能跑起来。

## wink 是怎么做出来的

1. 以 `v3/expr/E1_default.png` 为底（整脸、嘴型、腮红、发饰、耳朵、轮廓全部逐像素保留）；
2. 在**闭眼侧眼区** `x 570–960 / y 1070–1380` 内，与 `v3/expr/E2_blink.png` 求逐通道差（阈值 7/255），取出「闭眼笔迹」的像素集合；
3. 掩膜膨胀 4px 覆盖抗锯齿过渡带，只把这些像素替换成 E2 的像素；
4. 其余像素一个都不动。

选这条路而不是手绘新眼睑，理由：E2 的闭眼是同一角色、同一位置、同一光照下的既有笔迹，复用后 **blink 与 wink 的眼睑笔触完全一致**，不会出现两套画风；手绘则要重新对形、对色、对边缘。代价与边界见「已知取舍」。

## 门禁断言（`check-wink.mjs`）

| 断言 | 守的是什么 |
| --- | --- |
| C1 / C1b | 文件存在可解码；v3 基线可解码（历史交付完好） |
| C2 / C2b | 画布 2048×3072 与 v3 一致；8bit RGBA、非隔行（straight alpha 容器） |
| C3 | 差异像素 > 0（不许把 E1 原图当 wink 交上来） |
| C4 | 差异像素 < 90,000（防整头重绘 / 整体滤镜；单眼笔迹量级约 5 万） |
| C5 | 差异包围盒 ⊆ 单侧眼区 `570–960 / 1070–1380` |
| C6 | 眼区之外差异 = 0（嘴型/腮红/发饰/耳朵/轮廓一字未动） |
| C7 | 另一只眼区差异 = 0（另一只眼必须还睁着） |
| C8 | 睁眼侧与 `E2_blink` 必须不同（排除「双眼闭合冒充 wink」） |

## 人工复核（`preview.html`）

直接双击打开（`file://` 即可，无需起服务）：

1. 左 E1、右 E9 并排；眼睛以下区域应该**纹丝不动**，只有画面左侧眼睑变了。
2. 点「闪切对比」：E1 与 E9 每 0.9s 交替叠放，任何「多动了的像素」都会跳出来（嘴、腮红、刘海、发夹）。
3. 「眼区框」可开关：闭眼侧虚线框内允许有变化，睁眼侧虚线框内必须**看起来一模一样**（数值上差异 0）。
4. 亮/暗底切换各看一遍：暗底最容易暴露半透明脏边与灰蒙。
5. 判据一句话：**一只眼闭着、另一只眼还亮着大瞳孔，嘴还是那个 :3 ⇒ 是 wink；两只都闭 ⇒ 是 blink；嘴型变笑 ⇒ 与 happy 混档，不合格。**

## 已知取舍 / 设计决策

- **闭眼笔迹直接复用 E2，而不是重画**：保证 blink 与 wink 同一笔触；代价是 wink 的眼睑弧度受 E2 限定（内角略微上挑，读作俏皮，符合设计 §5.3 的「弧线略上挑」建议），不存在「更夸张的手绘上扬」版本。若要更强的情绪辨识度，见「未决项」。
- **只用 diff 掩膜 + 4px 膨胀，不做矩形硬贴**：矩形硬贴会在脸部留下方形接缝；diff 掩膜保证边界外侧像素与 E1 的通道差 ≤7（肉眼不可见），因此无接缝、无需羽化。
- **不重跑 alpha 清理**：E9 的像素来自 v3 两个已清理过的母版，重跑清理会改变边缘像素从而破坏 C11（外轮廓必须逐值一致）。
- **wink 不参与眨眼调度**：本资产只提供画面；`blink` / `blinkHalf` / `wink` 的语义分离在表现层与行为层实现，见设计 §5.2。
- **`blink.half` 在 v4 显式置 `null`**：v3 的 `half: "sleepy"` 会让困倦嘴型随眨眼跳动；v4 明确置空并写进 `notDelivered`，避免下游继续借用 sleepy。

## 未决项

1. **wink 的情绪强度（需主理人拍板，非阻塞）**：当前交付 = 「复用 blink 笔迹」的克制版。若希望 wink 更有辨识度，有两条候选：
   - A（保守，即当前交付）：闭眼笔迹与 blink 完全一致，只有「单眼」这一个信号；
   - B（增强）：在闭眼侧眼区外加一笔很小的「眼角笑纹/上挑弧线」，仍严格限制在 `x 570–960 / y 1070–1380` 内 —— 门禁能继续守住，但眼睑笔触会与 blink 略有差异；
   - C（增强+联动）：wink 时同时微抬嘴角 —— **违反当前契约**（差异必须只落在眼区），需要先改架构师 §4 的差异窗口，不建议。
   默认按 A 交付；要 B 请回一句，我在同一套工具链上加一个 `--style=b` 开关。
2. **`blinkHalf` 资产仍未交付**：M1 不要求，行为层按设计 §5.2.3 走两态眨眼。若后续要半闭帧，需要美术另画 1 张（同样受单侧/双眼窗口约束）。
