本目录是 M2「walk（走路）」批次：主角「小云酱」的 8 帧站立行走循环，**左向 4 帧 + 右向 4 帧**。
`status = awaiting-static-review`：静态资产已交付、门禁已自检，等主理人验收；`review.fullBatchComplete = false`，
其余批次（run / jump / play / edge / side / mini）一律未开始，不得把本批完成度当整批完成。

| 项 | 值 | 理由 |

| alpha 清理 | a<8 清零、a≥248 提满、<4 native px 孤岛删除 | 保证 C2 干净 |

### 3.1 两帧的抬起脚不可分离（诚实声明）

`l4`、`r4` 在 90px 扫描带内只分出**一段**墨迹：另一只脚要么整只躲在支撑脚后、要么与裙摆/尾巴下缘在水平投影上连成一片。
因此这两帧的 `contactPoints.lifted` 写 `null`，并在 `contactPoints.note` 里标注原因；`footGeometry` 保留了 90 / 160px 两个带宽的
原始分段（`l4` 在 160px 带才出现位于 x≈511 的段，同时出现 x≈1196 的裙摆/尾缘假阳性），供人眼复核。
`check-walk.mjs` 的 C4c 会同时抓「少报」和「多报」：声明 `null` 而实测是两段 → 红；声明了脚而实测只有一段 → 红。

## 4. 判据与阈值（为什么这样定）

### C10 朝向判据：虹膜相对头部墨迹质心的水平偏移

- 算法：取墨迹上 40% 的「头部带」→ 找深蓝（`b≥120 && b-r≥70 && g≤165 && r≤120`）的 4 连通块 → 取**面积 ≥200 native px 且填充率 ≥0.35** 的最大块视为虹膜 → 其质心 x 减该带墨迹质心 x。
- 为什么能区分朝向：侧视下双眼长在面部平面上，面部朝向前进方向；头后侧被长发与后脑占据。因此**虹膜质心总偏向面朝一侧**，原图坐标里的符号就等于朝向符号（-1 左 / +1 右）。镜像一帧必然把符号翻过来。
- 为什么用填充率过滤：虹膜是近乎实心的圆块（实测 fill 0.41–0.50），蝴蝶结/裙摆的深蓝只出现在描边与阴影里（实测 fill 0.10–0.27）。不加这层过滤，r2 的蝴蝶结块（1205px, fill 0.27）会比虹膜更靠前而误判。
- 实测（native px，负数偏左 / 正数偏右）：l1 −152、l2 −116、l3 −117、l4 −139；r1 +186、r2 +162、r3 +202、r4 +148。左组均值 −131、右组均值 +174，**符号相反**。
- 阈值 `|偏移| ≥ 60`：最小实测 116，留 1.9× 余量。

### C10b 镜像自证：右向帧与左向帧镜像后的差异

把左向帧水平翻转后与右向帧逐像素比，差异像素占墨迹并集比例必须 ≥5%。若右向是左向镜像交付，该值会趋近 0。
实测最小值：r1 vs mirror(l3) 73.5%、r2 vs mirror(l2) 74.5%、r3 vs mirror(l3) 77.6%、r4 vs mirror(l2) 76.7%。

### C11 脚掌交替判据：支撑脚相对躯干质心的前后关系

- 算法：底部 90px 带内取水平墨迹段 → `contactY` 与整图最低点差 ≤3px 者为支撑脚 → 比较支撑脚中心 x 与躯干质心 x；`facing=-1` 时 x 更小为 front，`facing=+1` 时更大为 front。
- 断言：同向 4 帧相邻帧相位必须交替，且 front / rear 各 2 次。
- 实测：左向 l1 front(+145) / l2 rear(−187) / l3 front(+119) / l4 rear(−157)；右向 r1 front(+163) / r2 rear(−166) / r3 front(+169) / r4 rear(−169)。两组都满足 2/2 与相邻交替。
- 为什么不用「bbox 下半宽段」判脚：尾巴与裙摆也在下半身，会把最宽段判成支撑脚（早期版本就这样误判过）。

### C12 不对称部件侧别判据：尾巴必须在身后 / 蝴蝶结与云朵发夹必须在前方

- 尾巴代理：下半身粉白羽簇（`r>225 && r-g>20 && g>150 && b>150 && |g-b|<25`）质心相对水平包围盒中心的偏移；断言 `偏移 × facing ≤ −40`。
- 蝴蝶结/发夹代理：头部带浅蓝簇（`b-r≥45 && b≥150 && g<b-20`）质心相对包围盒中心的偏移；断言 `偏移 × facing ≥ +15`。
- 实测（归一化后，8 帧一致）：tailNorm −108 / −140 / −153 / −194 / −165 / −166 / −152 / −145；bowNorm +42 / +40 / +45 / +33 / +93 / +383 / +85 / +426。
- 为什么有用：它能抓「部件被搬到错误一侧」——变异 M5 把 r1 的蝴蝶结+云朵发夹整体搬到身体另一侧后，bowNorm 由 +93 翻成 −92，C12 立刻变红。
- **诚实的局限（重要）**：一条完美的镜像帧在几何上是自洽的——尾巴镜像后仍在身后、蝴蝶结镜像后仍在面朝一侧，因此 **C12 单独抓不住「右向其实是镜像」**。
  这一点已用变异 M1 实证：把 r2 换成 l2 的镜像后，C10a 与 C12 都还是绿的，只有 C10b 变红（镜像差异 0.0%）。
  所以本批把**镜像检测的主判据放在 C10b**（右向帧与任一左向帧水平翻转后的差异必须 ≥5%，实测最小 73.5%，14× 余量），
  C12 负责「侧别一致性 / 部件错位」，两者互补。
- 另一个局限：浅蓝簇同时包含裙上的蓝色蝴蝶结装饰，是个**粗代理**；只用于判侧别，不用于判精确部件位置。

## 5. 体积（未达 8MB 目标，如实报数）

- 8 个母版合计 **12,846,431 B = 12.25MB**；单张最大 1,731,309 B（l4），**低于 2.5MB 编码红线**。
- `tools/png.mjs` 已启用自适应行滤波（逐行在 0..4 里挑残差绝对值和最小的）+ `deflate level 9`，没有剩余可无损压缩的余量；
  8 帧像素两两不同、sha256 全不相同（`volume.distinctMasterSha256 = 8`），**不存在可用 alias 去重的同像素帧，也没有存任何物理重复副本**。
- 为什么超：本批画布是 3072×3072、角色墨迹约 2060×2740，8 帧就是 8 份不同绘制。参照 sleep 批次：5 张母版 7.54MB ≈ 1.5MB/张，
  同样编码器、同样画风下 8 帧的物理下限就在 12MB 量级。**8MB / 8 帧 / 3072² 三者与当前画稿精度不能同时成立**，请主理人裁决：
  ① 接受本批 12.25MB（单张仍远低于 2.5MB 红线）；或 ② 允许 walk 母版降到 2048²（约 四分之三 体积，但与「站姿系 3072²」口径不一致）；
  ③ 允许提高压缩档（会引入有损，不建议）。
- `check-walk.mjs` 的 C9 把「单张 ≤2.5MB」与「合计 ≤13.2MB」写成断言（后者是本批实测的守门值，不是把规格放宽成恒真：
  一旦编码器退化（比如换回固定 filter=0）体积会明显上涨并触发红）。

## 6. 怎么一眼辨伪

1. `qa/walk_review.png`：亮底/暗底两排，8 格同尺度（母版 3072 → 320，统一 0.10417）。每格标签是 `帧号 + 朝向字母 + 相位字母`：
   `F` = 支撑脚在身体前方，`B` = 支撑脚在身体后方。**左排 L1–L4 与右排 R1–R4 的 F/B 都是交替的**，一眼能看出不是「一套步态换个朝向」。
2. 看脸：左向帧的虹膜在头部偏左，右向帧偏右（C10 实测差值 116–202 native px ≈ 24–42 display px，肉眼看得出）。
3. 看不对称件：**蝴蝶结与云朵发夹永远和脸在同一侧**，尾巴永远在身后。若有人拿左向帧镜像冒充右向，蝴蝶结与尾巴会同时翻边。
4. 看脚：支撑脚贴地、另一只脚离地 8–67 native px；4 帧一组内 F/B 交替两次。

## 9. 未决项

1. **体积**：12.25MB > §1.8 的 8MB 目标，需要裁决（见 §5，三条路）。
2. **画布口径**：本批按 3072×3072，与总规范 §4 的站姿系 2048×3072 不一致，请确认以本批为准。
3. **左右脚命名**：侧视轮廓无法判定哪只是解剖意义上的左脚/右脚，`contactPoints` 用 `support` / `lifted` + 相位（front/rear）记录，
   这是可机验的口径；若引擎需要严格 left/right，需要美术侧补充侧别约定（例如「近侧=左」）。
4. **C12 代理精度**：浅蓝簇含裙上蝴蝶结，只用于判侧别；若后续表情/服装改动引入大面积蓝饰，阈值需重新标定。
5. **C9 合计阈值 13.2MB**：为本批实测守门值，不是规格。若裁决降低画布，该阈值应同步下调。

## 10. 变异自检（5 例，全部实跑）

规则：变异 → 重算 manifest（`mkmfst`，保证 C4 类对账不因 sha 变化而误红）→ 跑 `check-walk.mjs` → 还原字节 → 再跑。
5 例都在「还原后 sha256 逐字节一致」的前提下回绿（19/19 PASS，退出码 0）。

| 例 | 变异内容 | 变异后退出码 | 命中断言（原样） | 还原后 |
|---|---|---|---|---|
| M1 | 把 r2 换成左向 l2 的水平镜像（母版与 native 同时换） | 1 | `FAIL C10b ... r2:min vs mirror(l2)=0.0%` | 字节一致，退出 0 |
| M2 | 让 l3 := l2（同向两帧同脚在前） | 1 | `FAIL C11 ... 左向[l1:front l2:rear l3:rear l4:rear] front=1 rear=3 交替=否` | 字节一致，退出 0 |
| M3 | 在 l1 的 native (2,2) 点一个声明区域外的像素并重建母版 | 1 | `FAIL C2b l1:1`、`FAIL C3a min=4px`、`FAIL C5 l1.width=2990,l1.height=2904`、`FAIL C12 l1:tailNorm=-325`（该点把 bbox 撑大，代理随之失真） | 字节一致，退出 0 |
| M4 | 篡改 manifest 里 r3 母版 sha256 的首字符 | 1 | `FAIL C4a files[] 母版/归一化图 bytes+sha256+bbox  r3.sha256` | 字节一致（manifest 与三张图 sha 均未变），退出 0 |
| M5 | 把 r1 的蝴蝶结+云朵发夹整体搬到身体另一侧（尾巴/腿不动） | 1 | `FAIL C12 ... r1:tailNorm=-165 bowNorm=-92`、`FAIL C10a r1:-350`（搬运块压到眼部，虹膜随之偏移；两条都是语义断言） | 字节一致，退出 0 |

M1 是最重要的一条教训：**完美镜像能过 C10a 与 C12**（因为镜像出来的右向帧自身是自洽的），只有 C10b 抓得住它。
本批因此把 C10b 定为镜像主判据，并在 C12 一节写明这个边界，不假装 C12 能替代它。
