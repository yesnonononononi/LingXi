### C6 的证据链（为什么这不是「主角缩小」）

单纯比较包围盒或宽高比都能被「先把主角缩到 244×208」绕过，所以 C6 用的是**尺度不变**的两个指标，
并让脚本自己校准上界：

| 量 | 实测 | 说明 |
| --- | --- | --- |
| 形状重合度 IoU（小云酱 vs 主角） | **0.7702** | 归一化到 64×64 覆盖率网格后比较，与显示倍率无关 |
| 自校准上界（主角降 32×32 再升回 64×64） | 0.9433 | 「同一形状，只损失分辨率」时的重合度，即缩放副本的上限 |
| 判定线 | < 0.7933 | 上界 − 0.15 余量 |
| 宽高比 | 小云酱 1.173 vs 主角 0.729（差 60.9%） | 横着长的云 vs 竖着长的人形 |
| 归一化细节密度 | 小云酱 0.0771 vs 主角 0.1425（差 45.9%） | 主角有发丝/衣褶/蝴蝶结等高频细节，小云酱是平涂云团 |

反向验证：把主角**干净地**缩成 244×208（alpha 清理过、2× 块对齐、锚点一致）当变异体跑，
`silhouetteIoU` 立刻从 0.7702 跳到 **0.9850**（贴着上界 0.9433），C6a/C6c 判红；
细节密度也从 0.1425 变成 0.1335（几乎不变，证明该指标确实尺度不变）。

## 制作流程（为什么这么做）

1. **绿幕生成**：位图模型给不出可信的透明通道，直接要「透明背景」只会得到一圈灰绿脏边。所以生成源用纯 `#00A651` 绿幕、并明确禁止投影（有投影就会被抠成一块半透明污渍）。
2. **数学抠像**：不是抠 RGB 距离，而是抠**绿色相对主导度** `(g − max(r,b))` 的软 matte——因为这角色主体是奶白色，RGB 距离法会把高光当背景吃掉。
3. **反预乘 + 去溢色**：按 `C = a·F + (1−a)·K` 反解前景色，再把绿通道钳到 `max(r,b)` 上限，边缘不会发绿。
4. **面积平均缩到原生 122×104**：在**预乘空间**做平均，否则半透明边缘会被拉灰。
5. **原生分辨率清理**：`alpha < 8` 归零、内部实心化到 255、删掉 < 4px 的孤块（沿用 v3 `alphaCleanup` 的 8/248 阈值口径）。
6. **整数倍 nearest 放大回 244×208**：保证「原生 256 画布 × 2」的母版约定成立（C7 就是守这条）。
7. **对齐贴图**：`left = 256 − 122 = 134`（偶数）、`top = 470 − 208 = 262`（偶数），块网格对齐画布；最低一行落在 **469**，它的下边缘正好压在锚点地面线 y=470 上——这比「最低像素中心压在 470」在几何上更准确，且偏差 1px 在 ±2px 容差内。

## 设计决策与理由

- **配色全部取自 `v3/palette.json`，不另起色板**：主体奶白 `#FDF7F0`（hair `#FEF2E4` / skin `#FEF6EC` / robe `#F9F9FA` 的同一色阶）、冷调投影 `#E7EAF2`、暖棕描边 `#8C5B47`（落在 outline `#A86D59`～`#8C4834` 之间）、腮红 `#F8CFCB`（对齐 inner_ear `#FEC1B6` 的粉调）、淡蓝发夹 `#B9C4D9`（呼应 scarf `#A1CBF9`/`#B0D7FE` 的蓝点缀）。并排不打架，是靠同一套色阶，不是靠调透明度。
- **尺寸取 244 宽（区间中上）**：区间是 180–260，取 244 让它在 1:0.40 显示倍率下仍有 55px 高可辨认表情；再小会看不清豆豆眼与 ω 嘴，再大就贴着上限，留给后续状态帧（跳起、被抱起）没有余量。
- **锚点让留白 42px**：正文要求的 42px 余量正好是「跳起/被抱起时下半部分还能动」的缓冲；所以最高优先级是「最低行不越过 470」，而不是「画满画布」。
- **正面朝向与主角一致**：主角立绘是正面，伙伴若是 3/4 侧面会显得两个角色不在同一空间。
- **发夹在画面左上，而设定图小图标画在右上**：这是 1px 级的位置差异，镜像一下即可对齐（`--mirror`）。默认未镜像，因为我更看重「云朵凸起 + 左右对称感」的平衡；要不要镜像请一句话确认（见未决项）。

## 规格存疑（需拍板，不阻塞本批）

正文写「可见包围盒 180–260 / 160–240（约为主角的 1/4–1/3）」。这两句话只有在**给定两块画布的显示倍率**后才同时成立，我按实测换算过：

| 假设 | 小云酱实际高度比 |
| --- | --- |
| 两块画布按相同 master 像素倍率显示（512 画布 = 主角 2048 画布的 1/4 大小） | 208 ÷ 1330 ≈ **1/6.4**（比「1/4–1/3」小） |
| 两块画布在屏幕上显示成同样宽度 | 208÷512 vs 1330÷3072 ⇒ 约 **1 : 1.07**（几乎等大，明显超出） |
| 小云酱画布按主角画布宽度的 0.40×–0.53× 显示 | **1/4.0 – 1/3.0** ✔（与正文一致） |

⇒ **建议**：把「1/4–1/3」写成引擎侧的显示约束 `companionCanvasWidth ≈ 0.40–0.53 × protagonistCanvasWidth`，
并让 `preview.html` 的四个倍率按钮作为对齐验收依据；资产侧不改任何参数（180–260 / 160–240 已满足）。
这一条只是口径落位问题，不影响本批交付物。
