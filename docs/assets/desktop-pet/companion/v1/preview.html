怎么一眼看出这是小云酱，而不是主角被缩小

  • 轮廓语言不同：小云酱是「一坨云」，外缘全是圆鼓鼓的凸起，没有四肢、没有脖子；主角有双马尾、兽耳、呆毛、蝴蝶结，外轮廓到处是尖端与凹口。
  • 比例相反：小云酱宽 244 / 高 208 ≈ 1.17（横着长）；主角 1690×1330 ≈ 0.73（竖着长）。缩放不会改变宽高比。
  • 脸占比不同：小云酱整只就是一个头（脸直接长在身体上）；主角是头身分离的 Q 版人形。
  • 细节密度：归一化到同尺度后，小云酱的边缘能量只有主角的 54%（0.0771 vs 0.1425）——头发丝、衣褶、蝴蝶结这些高频细节它没有。
  • 配色同族但不同角色：奶白主体 + 暖棕勾线 + 淡蓝云朵发夹，分别取自 v3/palette.json 的 hair/skin、outline、scarf 色阶，所以并排不打架，但形状一眼可分。
  • 机检数值见 node tools/check-companion.mjs 的 C6a / C6b / C6c 三条；把主角缩成同样的 244×208 当变异体跑，C6a 立刻从 0.7702 跳到 0.9850（贴着自校准上界 0.9433）并判失败。

比例怎么读（页面右上角的倍率按钮就是这个变量）

「小云酱约为主角的 1/4–1/3」这句话只有在给定了两块画布各自的显示倍率之后才有唯一解。 本页按「主角画布宽 340px」为基准：小云酱画布按它宽度的 0.40× / 0.47× / 0.53× 显示时， 角色实际高度比分别约为 1/4.0 / 1/3.4 / 1/3.0。点按钮切换即可看哪种读起来协调。

本页不做什么

  • 不做图像处理：放大用 image-rendering: pixelated，看到的就是母版原像素。
  • 不读取 manifest（file:// 下 fetch 被 CORS 拦），数字以 manifest.json 与校验脚本输出为准。
  • 地面线是虚线，只作对齐参考，不属于资产像素。
