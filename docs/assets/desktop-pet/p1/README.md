## 遮挡层与接入

**不能把六件直接重复叠在完整立绘上**：原立绘里已经有这些部件，会产生双影；隐藏补绘还必须压在前发、长袍等遮挡物下。附带的支持层解决这两个问题：

- `support/body-occluder.png`：移除六件可见像素后的原画主体，保留前发、衣物、脸等遮挡。
- `support/underpainting.png`：耳根、呆毛根部及蝴蝶结移开后露出的头发补绘。
- `support/foreground-occluder.png`：发根盖片及原云朵发夹，遮住隐藏根部和发夹下的左翼。
- `support/masks/*_visible.png` / `*_hidden.png`：可见像素归属与新增补绘区，均为完整母版画布。
- `support/reconstructed.png`：按清单顺序重组的静止帧。

实际渲染从后往前：头发补绘底层 → 尾根 → 尾尖 → 双耳 → 主体遮挡层 → 呆毛 → 头饰蝴蝶结 → 发根与云朵发夹盖片。需求单的 01～06 只能确定部件相对顺序，不能替代原立绘的实际遮挡关系。呆毛卷曲可见部分在前，插入头顶的隐藏根部仍由盖片压住。

`manifest.json` 的 `files[]` 登记全部 9 个渲染文件：6 个 `kind=part` 部件及 3 个 `kind=support` 支撑层。每项均有用途、width、height、sha256 和 bytes；`renderOrder` 与该清单必须一一对应。构建及验收检查实际尺寸和摘要，缺文件、漏登记、字节或尺寸变化均显式失败。

## 验收与复现

- `preview.png`：P0 原画与六件重组，深浅背景各一组。
- `qa/parts-light-dark.png`：六件单独显示的深浅背景图。
- `qa/offset-positive-10px.png`、`offset-negative-10px.png`：每件分别沿 X/Y 偏移 ±10px 的局部截图。
- `qa/rotation-check.png`：耳朵 4°、尾巴 1°、呆毛与蝴蝶结 3°的局部旋转图。
- `preview.html`：本地交互预览，支持原画/重组切换、支点显示、部件偏移和循环摆动。
- `qa/validation-report.json`：实际机检数据及金丝雀结果。

机检涵盖尺寸、RGBA8、sRGB、完整外边缘透明、合理区域、可见像素零差异、静止重组零差异、补绘存在、双向 10px 支点覆盖和左右耳非镜像。金丝雀主动注入错误色型、含 NUL 的文本块、缺件、不透明角点和可见像素篡改，确认检查确实会失败。

另逐个验证三个支撑层缺文件、漏登记、摘要篡改和尺寸篡改都会失败；P0 占位摘要及内容变化同样必须被拒绝。结果写入 `qa/validation-report.json` 的 `referenceSha256` 和 `supportChecks`。
