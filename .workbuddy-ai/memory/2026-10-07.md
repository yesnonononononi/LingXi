# 2026-10-07

## 修复：前端把 rootSessionId 的哨兵 0 当订阅键 → 后端 HTTP 500

**症状**：`java.lang.IllegalStateException: Unknown session: 0` @ `ExecutionIdentity.java:57`，对用户呈现为 500「系统繁忙，请稍后再试」。

**根因**：后端用 `Session.ROOT_SESSION_ID = 0L` 表示「自身即根」，`SessionVO.rootSessionId` 经 `ToStringSerializer` 把根会话下发为字符串 `"0"`；`services/chat.ts:493` 原样拷到 `ChatSession`；`useChatView.ts` 的订阅 watch 与 `ensureSubscribed` 用 `rootSessionId != null ? String(...) : String(session.id)` 解析 → `"0"` 非 null → 连接键 `'0'` → `GET /a/completion/0/events` → `subscribeSession` → `resolveRootSessionId(0)` 抛异常 → `GlobalExceptionHandler` 兜底 500。正确规则当时只存在于 `useChatSubSession.ts`（三处重复、两处错）。

**改动**：
- 新增 `frontend/src/utils/session.ts#resolveRootSessionId(session)` 作为唯一真源（temp→null；`declared && declared !== '0' ? declared : id`）。
- `useChatView.ts`（订阅 watch + `ensureSubscribed`）、`useChatSubSession.ts` 改为复用它，删除私有副本。
- `ChatServiceImpl#subscribeSession` 入口校验改 `throwIf(sessionId == null || sessionId <= 0, "会话标识不合法")`，把 500 收成业务错误。`stop/suspend/resume` 已确认传 0 不会 500，未动。

**验证（本人复核，非仅采信成员报告）**：
- `singleSessionStream.test.ts` 新增 `1c`（根会话 `rootSessionId:'0'`，断言订阅与发送两条路径的 URL 均为 `/{ROOT}/events` 且绝无 `/0/events`）。
- 变异证明：把 resolver 回退成 `return declared ?? id;` → `1c` 红（实际请求 `/a/completion/0/events`），`1b` 仍绿（证明 1c 覆盖的正是原先未覆盖的分支）；恢复后 20/20 绿。
- `npm test`：81 tests / 77 pass / 4 fail，4 条全部是既有 `reasoningEffort.test.ts` 失败（基线 80/76/4，无新增失败）。
- `npm run build`：`EXIT=0`，`vue-tsc -b` 无报错。
- `mvn -o test -Dtest=ChatSubscribeSessionIdTest`：3/3 BUILD SUCCESS。

**未决**：合法但不存在/已删除的 sessionId 仍会走 `IllegalStateException` → 500（未改 `ExecutionIdentity`，其内部调用方需要该抛出）。
