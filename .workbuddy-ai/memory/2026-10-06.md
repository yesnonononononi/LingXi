## 前端渲染两缺陷修复（GStack 团队：排障手 + 质量门神）

用户报告：① 回答气泡底部工具条（token 用量/耗时）不显示；② 同一会话第二条用户消息要等 AI 回答完成才渲染。

**根因（均在渲染层与「会话实体消息数组」的绑定）**
- 缺陷①：`useChatView.ts#buildTurnMap` 把每条消息的 `turn` **硬编码 null**，从不按 turnId 从 `session.turns`（`ChatSession.turns?: Record<string,ChatTurn>`）解析 → `ChatMessageItem` 的 `props.turn` 恒 null。且 `useChatHistory.ts` 的 reconcile / loadMore 用新数组替换 `session.messages` 时**丢弃了接口同页返回的 `turns`**（`fetchSessionMessages` 返回 data.turns）。`ChatMessageItem#displayDuration` 无摘要分支**缺 return** → 渲染 undefined。
- 缺陷②：reconcile 里 `cur.messages = msgRes.data.messages` **替换数组引用**，而 `streamSessionRouter.ts#bindRootSession` 在会话 id 不变时提前 return → `TurnStreamReducer` 始终持有 bind 时捕获的**旧数组**；第二轮 `pushUserMessage` 写进已脱离渲染的旧数组，直到本轮结束再次 reconcile 才随回答出现。子会话同病（`cur.subSessions = tree.subSessions` 也整体替换）。

**修复（11 文件：10 改 + 1 新增测试）**
- `utils/session.ts` 新增 `buildMessageTurnMap(messages, turns)`（turnId→ChatTurn 绑定 + 组尾）、`mergeTurns`（逐页 union，后到覆盖，缺失归一 `{}`）；复用既有 `groupMessagesByTurn`（USER 开新组 + turnId 变化拆组）。原 buildTurnMap 的局部分组不按 USER 边界拆组，会把旧数据（turnId 全 null）并成一组致工具条少显示，已改掉。
- `useChatView.ts` 两个 turnMap 改按 turnId 解析；`useChatHistory.ts` reconcile/loadMore 合并 turns 进 `session.turns`；`useChatSubSession.ts` + `SubSessionVO.turns` 打通子会话。
- `turnStreamReducer.ts` 构造函数入参 `ChatMessage[] | (() => ChatMessage[])`，内部一律走 `getMessages()`（兼容裸数组旧调用/测试）；`streamSessionRouter.ts` 根/子 reducer 传访问器，`bindRootSession` 同 id 仍先更新 `currentRootSession` 再 return。
- `format.ts` 新增 `formatDurationOrPlaceholder`；`ChatMessageItem.vue#displayDuration` 恒返回字符串。
- 新增 `frontend/tests/frontendRenderFix.test.ts`（5 条，已接入 `npm test`）。

**验证**：针对性 5/5；`npm test` 33/37（4 条 `reasoningEffort.test.ts` 失败经 `git worktree` 基线复跑证实**改动前即失败**，用例名逐字相同）；`vue-tsc -b --force` exit 0；`CODEBUDDY_SAFE_DELETE_ENABLED=0 npm run build` exit 0。
