## What's new

- Read an MCP server's full tool inventory, even when it has more tools than one listing can hold. `list_mcp_tools` now takes a `start` and `end` range in tool-name order, so a server with hundreds of tools can be walked a window at a time instead of only ever showing the first page.

## Improvements

- The default listing returns the first 20 tools instead of up to 50, keeping the common "show me what this server offers" call cheap while a single window remains capped at 50.
- Each listing reports the range it actually read and whether more follows, so both the model and the usage panel can tell which slice of the inventory is on screen.
- A server holding more tools than one window can carry is no longer partly unreachable: previously anything past the first 50 could only be found by blind search.
- A malformed or out-of-range window is clamped rather than failing the round.
- Upgrade the harness framework to 1.1.6 and pin the exact commit in the dependency lock.
