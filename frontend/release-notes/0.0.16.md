## What's new

- Question cards were rebuilt around the question itself. The question now sits in the card header next to a `‹ 1 / 4 ›` navigator, each option is a full-width row with its number, label and an arrow, and the selected row is highlighted as a whole. Free-form answers became the last row of the same list: click "Other…" and type right there instead of a second text box appearing underneath.
- Question cards advance on their own. Picking an option moves to the next question immediately; the last question stays put instead of wrapping around, and the free-form row never advances while you type.
- While an approval, question or plan card is waiting for you, the chat composer steps out of the way and the card takes its place. The paused-run hint disappears with it — it was only restating what the card already says, with a resume button that could not be pressed until the card was answered.
- Dark theme accent is now pure white. Selected options, dropdown selections, the "Other…" row and the team picker all use a white glowing outline and a white-tinted fill; the cyan and blue accents are gone, and the card background is true black with glowing text.
- Question cards keep a constant size. The question title holds two lines and the option list holds a fixed viewport that scrolls, so switching between questions no longer makes the card jump in height.

## Improvements

- Process rows share one type size (13 px) and one colour set. The terminal description used to render a size and a shade smaller than every other tool row; it now matches them, while the "thinking" title stays one shade dimmer on purpose so it still reads as narration rather than action.
- `manage_command` reads as "Check background task status" in the tool row and in tool settings, replacing "Manage background commands".
- Failure notices no longer leak exception class names into the UI; only the classified message is shown.
- The theme equivalence gate now refuses to compare against a stale build artifact and reports the resolved token values per theme, with a self-check that proves the resolver works.
- Theme tokens were recomputed class-for-class and a `border-faint` token was added, so the light and dark palettes stay byte-equal to what the components used before.
- The multi-question submission path was split into explicit steps (validate → resolve ownership → apply), and the teammate-state tool now carries the display-name argument the model is expected to send.
